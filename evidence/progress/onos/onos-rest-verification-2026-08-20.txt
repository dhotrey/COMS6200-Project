Date: 20 August 2026
Purpose: verify that the ONOS 2.7.0 REST API can serve the diagnostic evidence
the project's Python tool layer will later require.

CREDENTIAL HANDLING
All requests used HTTP basic authentication against localhost. Credentials were
supplied on the command line at test time and are NOT recorded here. No
authorization headers, passwords or tokens appear in this file or anywhere in
the repository. Requests are shown in the redacted form:

  curl -sS -u "$ONOS_USER:$ONOS_PASSWORD" http://127.0.0.1:8181/onos/v1/<endpoint>

Base URL: http://127.0.0.1:8181/onos/v1   (loopback only)

=====================================================================
D. SUITABILITY FOR THE PLANNED ARCHITECTURE
=====================================================================

Intended data path, now demonstrated end to end:

  Python tool layer
        |
        REST      (HTTP 200 on devices, ports, links, hosts, flows, topology)
        |
       ONOS 2.7.0
        |
   OpenFlow 1.3   (OVS: [OpenFlow13], OFPT_FEATURES_REPLY (OF1.3);
        |          ONOS: protocol=OF_13)
 Mininet / OVS    (6 switches, 8 hosts, 17 links)

Conclusion: the read-only endpoints needed for later structured telemetry
(devices, ports, links, hosts, flows, topology) all respond over localhost
REST with HTTP 200. No unrestricted shell access to the network is required by
the future agent.

NOT DONE IN THIS MILESTONE
  - No write/POST operations were issued to ONOS.
  - No telemetry abstraction, fault injector, LLM agent or deterministic
    baseline was implemented.
  - No credentials were stored in the repository.
